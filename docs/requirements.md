# 요구사항 명세서 (김혜린 작성, 9/11)

> 2026-09-11 로컬 데이터(`sprint_ai_project1_data/`) 직접 검사로 확정. 이전에 팀이 가정했던 수치 중 일부(클래스 수)가 크게 달랐음 — 아래 ⚠️ 표시 확인.

## 1. 문제 정의
- 입력: 알약 사진 1장 (`.png`, 예: 976×1280)
- 출력: 사진 속 각 알약의 **class(약 이름) + bbox(x,y,w,h, 픽셀 절대좌표)**, 이미지당 최대 4개
- 검증: Kaggle Private Competition (`ai14-level-project`)

## 2. 데이터 실측 (⚠️ 기존 가정 수정)
| 항목 | 기존 가정 | 실측값 |
|---|---|---|
| 클래스(약 종류) 수 | ~2000종 | **56종** |
| 학습 이미지 수 | ~200장 | **232장** |
| 고유 장면(알약 조합) 수 | ~40개 | **114개** |
| 장면당 이미지 수 이유 | 상하/좌우 반전 | **촬영 조건(조명·각도) 차이** — JSON에 `light_color`·`camera_la`·`camera_lo`·`back_color` 필드로 기록됨. 반전 증강 아님 |
| 이미지당 알약 수 | 최대 4개 | 조합 114개 중 89개=3개, 25개=4개 |
| 테스트 이미지 수 | ~800장 | **842장** (파일명 `1.png~1500.png` 중 일부, 정답 정보 없음) |

**의미**: 클래스 커버리지 문제가 예상보다 훨씬 작을 가능성 높음(2000종이 아니라 56종). 다만 촬영 조건 다양성(조명·각도)에 대한 일반화가 새로운 핵심 과제로 부상. 외부 데이터 수집의 우선순위를 "커버리지 확장"에서 "촬영 조건 다양성 확보"로 조정 검토 필요 — 9/16 게이트에서 논의.

## 3. 라벨 포맷 (⚠️ 신규 확인 사항)
- COCO 스타일 JSON이지만 **이미지당 1개가 아니라 알약 1개당 JSON 파일 1개** (`train_annotations/<조합>_json/<약코드>/*.json`)
- 같은 이미지에 대해 알약 개수만큼(3~4개) JSON이 따로 있음 → **학습 전 이미지 단위로 병합 필요** (강인호 전처리 1순위 작업)
- bbox = `[x, y, width, height]` 픽셀 절대좌표 (정규화 안 됨)
- `category_id` = 실제 약 코드, `category.name` = 실제 약 이름 (예: "가바토파정 100mg")
